## Docker и комплект финальной сдачи

Dockerfile, Compose, пример окружения и скрипт проверки входят в комплект. Статически проверены структура Compose, значения по умолчанию и приоритет переменных-алиасов. `scripts/smoke.py` прошёл на хосте: четыре статических ресурса, 21 документ и 637 фрагментов, позиции цитат, уточнение даты с продолжением «2024», две строки CSV; вызовов моделей не было.

В локальной среде подготовки отсутствовал Docker Engine. Фактическая сборка образа, запуск контейнера и HTTP health затем успешно проверены на GitHub Actions: [запуск #1](https://github.com/Mits2406/psb-legal-assistant/actions/runs/43848023770), коммит `e55c8ce5aa0f9f9a11be6fbe1dbdda10a7864edb`, 16 ноября 2026 года.

[GitHub Actions](../.github/workflows/checks.yml) настроен на Python-тесты, тесты истории, побайтовую проверку пересобранного архива V20, сборку и запуск Docker, проверку HTTP health. Workflow запускается при `push`, pull request или вручную. Первый запуск успешно завершён; ссылка выше фиксирует проверенный коммит. Последующие запуски доступны на странице Actions репозитория.

Проверить на машине с Docker:

```sh
docker compose up --build -d
docker compose ps
docker compose run --rm web python scripts/smoke.py
docker compose down
```

После подключения целевого API отдельно проверить состояние `/api/health`, фактический вызов генерации, доступность embeddings и реранкера, задержки и обработку ошибок. Отсутствие ошибки в офлайн-режиме не означает успешного подключения LLM.

## Локальный эксперимент V19: реранкер включён / выключен

Это отдельный предыдущий эксперимент, полезный для диагностики архитектуры. Он **не является оценкой V20, настоящего Qwen или DeepSeek на платформе**.

Условия:

- 18 публичных вопросов организаторов, без изменения формулировок, `reference_date=2026-11-16`, один рабочий поток.
- Генерация и реранжирование выполнялись локальным адаптером Luna; векторный поиск был выключен.
- Сначала выполнен режим ON, затем OFF. Эталоны оставались у оценщика, генератор и реранкер их не получали.
- Код и входные данные внутри фаз совпадали. Предварительно задана рубрика: 0 — существенная ошибка, 1 — неполнота, 2 — полный ключевой смысл и необходимые источники. Дополнительно выполнено независимое сравнение со скрытыми названиями режимов.
- Для вопросов 4, 13 и 17 проведено по два дополнительных повтора в обоих режимах. Всего 48 конечных ответов.

| Метрика основного прогона | Без реранкера | С Luna-реранкером |
|---|---:|---:|
| Полный ключевой смысл и обязательные источники по нашей рубрике | 16/18 | 17/18 |
| Принятые модельные ответы | 18/18 | 18/18 |
| Средняя задержка | 9,51 с | 13,12 с |
| Медиана задержки | 10,11 с | 12,70 с |
| Невалидные точные цитаты | 0 | 0 |

Смысловое улучшение основного прогона относится к одному вопросу о неподтверждённом повышении арендной платы. Оговорка воспроизвелась 3/3 с реранкером и отсутствовала 3/3 без него. Вопрос 13 оставался неполным в обоих режимах во всех повторах; в вопросе 17 полнота объяснения была нестабильной.

Все 76 цитат из 48 ответов дословно сверены с корпусом. Это подтверждает точность цитирования, но не полноту юридического обоснования. После реранжирования вырос объём контекста: в двух вопросах с 2 до 40 фрагментов без улучшения ключевого ответа. Поэтому различие результатов нельзя приписать только перестановке одних и тех же фрагментов.

Материалы: [смысловая оценка](../evaluation/v19-luna/quality_report.txt), [технический отчёт](../evaluation/v19-luna/primary_technical_report.txt).

## Следующая проверка качества

Нужен независимый набор вопросов, не использовавшийся при настройке, и доступ к моделям организаторов. Следует фиксировать версию кода, конфигурацию, базу, модель и фактически применённые стадии поиска. Отдельно измерять:

1. Правильность и полноту ответа, выбор редакции, условия и исключения.
2. Обоснованность утверждений источниками, а не только существование цитат.
3. Корректность уточнений и отказов; отсутствие лишних уточнений при достаточных данных.
4. Медиану и p95 времени, частоту ошибок, тайм-аутов и возвратов к текстовому поиску.
5. Эффект BM25F, BGE и реранкера при одинаковой модели генерации и нескольких повторах.

Экономию времени сотрудников и снижение числа ошибок можно оценить только в пилоте с участием юристов. Числа ускорения других продуктов не являются результатами этого MVP.
